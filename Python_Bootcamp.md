# 0. BOOTCAMP PHILOSOPHY

This bootcamp is not “Python for Data Analyst.”

It is:

**Programming with Python first**
→ **problem solving**
→ **core Python tools**
→ **NumPy / Pandas**
→ **HackerRank introduction**
→ later branch toward **AI / ML / DE**.

The central transformation is:

**Current**
Problem  
→ ask AI  
→ AI writes code  
→ read / modify output

**Target**
Problem  
→ reason  
→ write pseudocode  
→ write first attempt  
→ debug  
→ ask AI only when needed  
→ rewrite independently  
→ explain the solution.

The bootcamp is successful only if independent coding ability increases.

# 2. DAILY TIME MODEL

Typical target:

**45–60 minutes/day**

But time is not the real completion criterion.

A session may finish earlier or run longer when justified.

The important rule is:

> **STOP WHEN THE LEARNING OBJECTIVE OF THE DAY HAS BEEN ACHIEVED.**

Do not continue endlessly just because more questions can be generated.

## Stop condition for a normal learning day

The day is considered complete when all four are true:

1. You can explain the main concept in your own words.
2. You have written at least one independent solution from a blank screen.
3. You have corrected the most important mistake made that day.
4. You can solve the final mandatory task with acceptable independence.

Once these are satisfied, **stop the session**.

More practice is optional.

## If the session is incomplete

### Case A — Time-incomplete
You understand the concept but run out of time.

Status:
**PARTIAL — TIME**

Next session:
finish the remaining task first, then continue to the next Day if reasonable.

### Case B — Competency-incomplete
You still cannot use the concept independently.

Status:
**PARTIAL — COMPETENCY**

Next session:
do **not** move forward yet.

Repeat / simplify / use a variant until the concept reaches an acceptable level.

# 3. NON-NEGOTIABLE RULES

1. **Attempt before AI.**
2. **No copy-paste of AI solutions as your own work.**
3. Most exercises must begin from a blank editor.
4. AI is tutor / reviewer / debugger — not the default coder.
5. When AI gives substantial help, rewrite the solution independently when the task is important.
6. Do not study two new programming languages in parallel during this bootcamp.
7. Do not turn every Python exercise into a data-analysis task.
8. Do not skip fundamentals to reach Pandas faster.
9. Do not inflate project ownership.
10. Do not convert normal 45–60 minute sessions into 3–6 hour marathons unless you deliberately choose to.
11. No mandatory homework outside the learning session.
12. If a concept is genuinely failed, repair it before moving on.

---

# 4. AI HELP LADDER

When stuck:

**Level 0 — Self attempt**  
Read the problem, reason, write something.

**Level 1 — Conceptual hint**  
Ask what concept might apply.

**Level 2 — Directional hint**  
Ask what next step should be considered.

**Level 3 — Pseudocode hint**  
Ask for logic without Python code.

**Level 4 — Partial code / pinpoint bug**  
Ask for the smallest technical intervention needed.

**Level 5 — Full solution**  
Only when necessary.

There is no absolute ban on Level 5.

But if Level 5 is used on an important task:

> Close the answer → open a blank editor → rebuild the solution yourself.

# 5. DAILY SESSION TEMPLATE

A normal session should roughly follow this sequence.

### 1. Quick recall
Optional, usually 3–5 minutes.

Recall something from the previous day without notes.

### 2. Learn the new concept
Length varies by topic.

Explanation → small example → guided attempt.

### 3. Progressive practice
Prefer:

**easy → medium → challenge**

Not every day needs the same number of exercises.

### 4. Mandatory blank-screen task
The key task of the session.

No copying.

### 5. Review / debugging
Discuss mistakes with AI.

### 6. Rewrite when needed
Especially if AI materially helped.

### 7. Close the session
Once the stop condition is satisfied.

## Rules for Writing Daily Updates

1. The update must reflect what actually happened in the session. Do not manufacture achievements, mistakes, or independence.
2. Do not give a high score merely because the final code works.
3. AI-assisted correctness and independent correctness are different and must be described separately.
4. If Minhyi initially fails but later solves the task after a hint, record both stages.
5. If AI gives a full solution, this must reduce the independence assessment unless Minhyi later rewrites it successfully from a blank screen.
6. Prefer specific observations over motivational filler.
7. The daily update should be detailed enough to act as context for the next chat, but should not become a transcript of the whole session.
8. Keep terminology and section order consistent across all days.
9. For Checkpoint / Project / Timed Challenge days, additional sections may be added when useful, but the core sections above must remain.
10. The purpose of tracking is to show progression from AI-dependent coding toward independent programming.

# 7. SCORING

Use a 1–5 overall score.

The score should consider:

- correctness,
- independence,
- reasoning,
- syntax fluency,
- debugging,
- explanation,
- task difficulty.

Independence matters more than elegant code.

### Rough interpretation

**1 / 5**  
Could not meaningfully attempt.

**2 / 5**  
Understood parts but required heavy guidance.

**3 / 5**  
Can solve basic tasks with some hints.

**4 / 5**  
Mostly independent, mistakes are fixable.

**5 / 5**  
Independent, correct, can explain and adapt the solution.

The score is diagnostic.

There is no “bootcamp failure” because of one low score.

# 8. ABSENCE / INTERRUPTION RULE

No punitive streak reset.

## Short interruption: 1–3 days
Continue from the unfinished Day.

A short 10–20 minute catch-up may be used if needed.

## Medium interruption: roughly 4–9 days
Continue from the unfinished Day.

Use a short warm-up before new material.

## Long interruption: around 10+ days
Use a dedicated **RE-ENTRY DAY** before continuing.

The re-entry session should:
- recall recent concepts,
- solve 2–4 representative tasks,
- identify what has actually been forgotten,
- then resume.
